### `CodeDiff` Config comparison (Change - same config, old and new form)
- Use when: A config file or snippet moves from an old format to a new one; The two forms are equivalent and the audience should compare them line by line
- Avoid: Only a few setting values changed: use CompareTable; More than 8 lines of code: cut to the key part or split across two slides
- Limits: before / after 2–8 lines each, ≤ 52 characters per line; label ≤ 12 chars; file takes the full path; mark is a zero-based line number; notes 2–3: key ≤ 12 characters (monospace), text ≤ 30 chars
- Reference: src/decks/release slide `deb822`; docs/en/components.md#code-diff; interaction: The two panes slide in one after the other and code fades in line by line.

### `SpecSheet` Version table (Change - old and new versions of a set of components)
- Use when: A batch of version numbers in a distro, dependency or platform upgrade; The audience should spot which ones are major jumps
- Avoid: Fewer than 3 components: use KeyValue or CompareTable; Values are behaviour descriptions, not versions: use CompareTable
- Limits: groups 2–3, 3–6 rows each, row counts within 1 of each other; name ≤ 12 characters; from / to ≤ 10 characters; major marks a major version change only, never every row
- Reference: src/decks/release slide `versions`; docs/en/components.md#spec-sheet; interaction: Groups fade in one by one; hovering a group lights its icon.
