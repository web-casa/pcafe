### `IndexStack` Index stack (Structure - One slide for 3–5 items, one at a time)
- Use when: Walk through 3–5 modules on one slide; Each module has a small data set
- Avoid: Modules need a side-by-side comparison: use PanelCards; More than 5 items
- Limits: items 3–5; label ≤ 8 chars, title ≤ 10 chars, body ≤ 40 chars; ui is the same as PanelCards; Set build: "focus" on the SlideDef
- Reference: src/decks/launch slide `stack`; docs/en/components.md#index-stack; interaction: Press → to bring the next card to the front; on a direct jump all cards start stacked

### `Orbit` Orbit (Structure - One core and what surrounds it)
- Use when: Ecosystem, integrations, tech stack, partners; Show that all of these connect to one thing
- Avoid: Nodes have an order or a dependency: use FlowDiagram; More than 8 nodes
- Limits: nodes 4–8, label ≤ 6 chars; points 0–3, each ≤ 22 chars; center.label ≤ 8 characters
- Reference: src/decks/launch slide `orbit`; docs/en/components.md#orbit

### `Pyramid` Pyramid (Structure - layers of dependent conditions)
- Use when: Preconditions, levels, layers of need; The layer below is the basis for the one above
- Avoid: The layers do not depend on each other: use LayerStack; You need to show a falling count: use Funnel
- Limits: levels 3–5: label ≤ 8 chars, note ≤ 30 chars; title ≤ 2 lines × 8 chars
- Reference: src/decks/toy3d slide `ship`; docs/en/components.md#pyramid

### `Concentric` Concentric circles (Structure - from the core outward)
- Use when: Core versus edge, reach of influence, layers of a contents list; Each ring encloses the one inside it
- Avoid: The layers stack vertically: use ArchLayers; One core plus parallel satellites: use Orbit
- Limits: rings 3–4: label ≤ 6 chars, note ≤ 30 chars
- Reference: src/decks/toy3d slide `rings`; docs/en/components.md#concentric

### `NodeGraph` Node graph (Structure - what connects to what)
- Use when: Relations between 4–10 objects: dependency, flow, cooperation; Explaining what a system is made of and how the parts affect each other
- Avoid: There is a sequence of steps: use FlowDiagram; Quantities flow: use Sankey
- Limits: nodes 4–10: label ≤ 6 chars, sub ≤ 10 chars; edges ≤ 14, label ≤ 6 chars; note ≤ 60 chars; the first node is centered by default; when every node has x/y (0–100) the manual positions are used
- Reference: src/decks/v2-p4 slide `graph`; docs/en/components.md#node-graph

### `AnatomyCard` Anatomy card (Structure - what one thing is made of)
- Use when: Break down the parts of an object, request, message or record; Every part has a concrete example value
- Avoid: Parts depend on each other top-down: use LayerStack or ArchLayers; No example values: use NumberedColumns
- Limits: label ≤ 24 Latin characters; parts 2–4; name ≤ 8 chars; sample ≤ 3 lines × 36 Latin characters; note ≤ 40 chars; weight 1–3
- Reference: src/decks/v3-p5 slide `anatomy`; docs/en/components.md#anatomy-card; interaction: build: reveal — each step lights one strip; in the complete state all are lit

### `StackBars` Stepped layers (Structure - horizontal bars offset layer by layer)
- Use when: A layered structure: a technology stack, an organisation hierarchy or priorities; Layers that depend on the ones below
- Avoid: The layers have a quantity relationship: use Funnel or Pyramid; Each layer needs a detailed explanation: use LayerStack
- Limits: layers 3–6, top to bottom; name ≤ 8 chars; note ≤ 20 chars; slide title ≤ 22 chars
- Reference: src/decks/sig-broadside slide `stack`; docs/en/components.md#stack-bars; interaction: Press → layers appear one by one
