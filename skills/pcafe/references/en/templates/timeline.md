### `Timeline` Timeline (Time - periods and roadmap)
- Use when: Support periods, contract terms, release roadmaps, project phases; The audience should feel how much time is left
- Avoid: Only one date: put it in Cover's facts; More than 3 rows: split across two slides; Events are discrete points, not ranges: use StepTrack
- Limits: rows 1–3; ≤ 2 when countdowns are used; segments on each row are contiguous, 1–3 per row; A segment label must be shorter than the segment: ≤ 6 chars for a one-year segment; countdowns ≤ 3; About half a year of blank space at each end of the axis
- Reference: src/decks/release slide `lifecycle`; docs/en/components.md#timeline; interaction: Segments grow in sequence; today and the countdowns are computed from the current date on every open, so the deck never expires.

### `ReleaseTrain` Release train (Time - overlapping version lifecycles)
- Use when: Support periods of software versions or product generations overlap; Showing how many versions are maintained right now
- Avoid: Dates but no spans: use Milestones; A span over 6 years: the bars get too short, so split the slide
- Limits: rows 3–6, in time order; version ≤ 10 characters; note ≤ 20 characters; start / end / from / until / today are written YYYY-MM; a span of 18–48 months fits best; todayLabel ≤ 8 chars; Dates that are estimates need estimate set and a note in source
- Reference: src/decks/v3-p1 slide `lifecycle`; docs/en/components.md#release-train; interaction: In build mode, each press → one row appears
